① 快速开始

模型网关是一个 OpenAI 兼容的统一入口：把多个上游供应商（Qoder、MOSS、DeepSeek……）聚合成本地平台模型，提供密钥池轮换、故障转移、并发/限流、统计与日志。

  1. 添加供应商：「供应商」页 → 新增供应商，填名称、Base URL、API Key（可多把组成密钥池）。
  2. 导入模型：点「获取模型列表」拉取上游可用模型，勾选导入。
  3. 创建平台模型：「平台模型」页 → 新增，对外名称（业务名）+ 选择成员（供应商 › 模型），设权重与优先级。
  4. 发客户端密钥：「密钥」页 → 新建密钥，复制 sk-… 给调用方。
  5. 调用验证：平台模型列表点 ⚡测试，或直接用下方 curl/SDK 示例。

接入地址：http://<host>:2325/v1（本页所有示例中的地址会自动替换成你当前访问的地址）。

② 调用方式

查看可用模型：

curl http://localhost:2325/v1/models -H "Authorization: Bearer sk-你的密钥"

对话（非流式）：

curl http://localhost:2325/v1/chat/completions \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{"model":"smart-fast","messages":[{"role":"user","content":"你好"}]}'

对话（流式，SSE 增量输出；统计 tokens 需在请求里带 stream_options:{"include_usage":true}，最后一块会带 usage）：

curl http://localhost:2325/v1/chat/completions \
  -H "Authorization: Bearer sk-你的密钥" -H "Content-Type: application/json" \
  -d '{"model":"smart-fast","stream":true,"stream_options":{"include_usage":true},"messages":[{"role":"user","content":"你好"}]}'

Python（OpenAI SDK，base_url 换成网关地址即可无缝接入）：

from openai import OpenAI

client = OpenAI(base_url="http://localhost:2325/v1", api_key="sk-你的密钥")
resp = client.chat.completions.create(
    model="smart-fast",                                  # 平台模型名或别名
    messages=[{"role": "user", "content": "你好"}],
    # stream=True,                                       # 需要流式时打开
)
print(resp.choices[0].message.content)

说明：model 填平台模型的「对外名称」或任一别名；鉴权用「密钥」页创建的客户端密钥，不是上游供应商的 key。

③ 供应商管理

  1. 新增：填名称、Base URL（自动补 /v1）、API Key（每行一个，多把自动组成密钥池）；可选「代理」让该供应商的上游调用经代理转发（留空直连）。
  2. 代理：支持 http://、https://、socks5://。注意填的必须是「容器网络可达」的地址——网关跑在容器里，127.0.0.1 是容器自身不可用；本机 mihomo 容器请填 http://mihomo:7890（已接入 my-pm 网络）。非法地址自动降级直连并在容器日志提示。
  3. 获取模型列表：拉取上游 /v1/models 目录，勾选导入到本地模型库。
  4. 启用/停用：点击状态徽章切换；停用后不参与任何调用，其成员自动故障转移到其他供应商。
  5. 密钥：进入密钥池管理每把 key 的权重、最大并发与限流（见⑤）。
  6. 删除：删除供应商不影响已导入的模型记录，但相关成员将不可用。
  7. 超时与重试：每个供应商可单独设「首字超时」「停滞超时」「超时重试次数」，留空=跟随全局（默认 120s / 300s / 1 次）。首字超时或网络错误时先在同密钥上重试，用尽再换密钥、换供应商；停滞超时（流式输出中途没新数据）只中止不重试。
  8. 额度耗尽 / 熔断：上游返回 402（余额不足）时整家供应商自动跳过（默认 30 分钟，可在设置里改），列表显示红色「额度耗尽」徽章；连续 3 次 5xx/网络失败则熔断 60 秒，显示「熔断中」。点「恢复」可立即解除两者。

④ 平台模型与负载策略

平台模型 = 对外提供的业务模型名。它由若干「成员」（供应商 › 具体模型）组成，请求按策略在成员间分流，失败时按优先级转移。

字段说明：

  • 对外名称：客户端 model 参数填的名字；别名：逗号分隔的等价名，同样能路由到本模型。
  • 负载策略：round-robin 加权轮询（按权重分流）；sticky 会话粘性（同会话尽量命中同一成员，配合黏性上限）；least-inflight 最少并发（把新请求发给当前最空闲的成员）。
  • 黏性上限：仅 sticky 生效，同一会话连续命中同一成员的请求数超过该值后重新选路，0=不限。
  • 最大重试成员数：一次请求最多尝试几个成员（默认 3）。
  • 成员权重：分流比例；优先级：故障转移顺序，数字小者优先；启用：关闭的成员不参与分流，只做备份。

例：A(权重 3, 优先级 0) + B(权重 1, 优先级 1) → 约 75% 请求走 A；A 失败/冷却/满载时转 B。

⑤ 密钥池：并发与限流

同一供应商的多把 key 按权重轮询分流；单 key 失败（401/402/403/408/429/5xx/网络错误）自动冷却并轮换下一把，冷却结束自动回归。

每把 key 可设三项限流参数（0=不限）：

  • 最大并发：该 key 同时处理的上限。新请求选 key 时跳过已满载的 key，自动落到下一把；全部 key 满载时返回 429（请稍后重试）。面板新建的 key 默认 3。
  • 限流次数 + 窗口(秒)：滑动时间窗限流，例如 5 次/10 秒 = 该 key 在任意 10 秒内最多 5 次请求；超限同样自动跳下一把，且不计入失败冷却。

列表里的「并发」徽章实时显示 当前并发/上限。被限流跳过不会写失败日志，只有真正发出的请求才记录。

⑥ 客户端 API 密钥

「密钥」页创建的是调用方密钥（sk-…），用于鉴权网关本身，与上游供应商的 key 无关。支持备注、复制、删除；先填备注再点「新建密钥」。

⑦ 统计页说明

  • 请求数：按「业务请求」计——一次客户端请求即使内部轮换多把密钥也只算 1 次；悬停可看尝试次数（含密钥轮换与失败重试）。
  • 错误数：最终失败的业务请求数（一次请求内部多次尝试失败但最终成功，不计错误）；成功率 = (请求数-错误数)/请求数。
  • 输入/输出 tokens：上游返回的 usage 口径（输入=提示词，输出=补全）；总 tokens = 输入+输出；大数自动显示为 万/亿，悬停可看精确值。
  • 平均缓存率：缓存命中 tokens ÷ 输入 tokens。
  • 范围：今天 / 近7天 / 近30天 / 全部 / 自定义起止；统计页每 10 秒自动刷新（仅页签激活时），也可点「刷新」手动刷。
  • 用量明细：按 日期 × 供应商 × 平台模型 汇总。
  • 首字 (ms)：流式请求从发出到收到首个内容块（含推理 token）的平均时间（TTFT）。
  • 解码速度 (tok/s)：纯生成速度 = 输出 tokens ÷ (总耗时 − 首字时间)，不含排队与首字等待；非流式请求或无首字记录（旧数据）时退化为「输出 ÷ 总耗时」。用量明细为分组累计口径，最近请求为单个请求口径。

⑧ 日志与调试

  • 日志记录每次尝试：时间、客户端密钥、平台模型、供应商、上游模型、上游密钥、延迟、tokens、结果与错误信息。
  • 支持服务端分页与按条件筛选；保存天数在「设置」里调整（默认 30 天，过期自动清理）。
  • 调试模式（设置页开关）：开启后记录客户端与上游的完整请求/响应报文（各截断 8KB），日志详情里可查看，排障用；默认关闭。

⑨ 系统设置

  • 管理密码：面板登录密码。
  • 日志保存天数：请求日志与统计的保留期，超期自动清理。
  • 对话超时：默认 600 秒，范围 10~1800；超过 600 秒面板会给出警告，因为挂起的上游请求会长期占住密钥并发槽。
  • 首字超时 / 停滞超时 / 超时重试：全局默认 120 秒 / 300 秒 / 1 次，填 -1 可关闭；供应商与平台模型可各自覆盖（模型优先于供应商，供应商优先于全局）。
  • 额度耗尽跳过时长：上游 402 后整家供应商跳过多久，默认 1800 秒。
  • 调试模式：记录完整报文，排障时打开，平时建议关闭。
  • 配置备份：可一键导出/导入完整配置（含管理密码、客户端密钥、供应商密钥），导入会整体替换现有配置，请务必保管好导出文件。
  • 登录保护：同一 IP 连续 5 次密码错误会锁定 60 秒。
  • 监控指标：/metrics 提供 Prometheus 文本指标（请求数、tokens、耗时直方图、首字直方图、供应商状态），可直接接入 Grafana/告警。

⑩ 错误码速查

  • 401 invalid_api_key：客户端密钥不对，去「密钥」页核对。
  • 404 model_not_found：模型名/别名拼错，或平台模型被停用。
  • 429 rate_limited：所有 key 的并发/时间窗限流都已满，稍后重试，或提高 key 的上限 / 增加密钥。
  • 首字前心跳：上游思考时间长（大上下文推理模型常见 10~60 秒）时，客户端可能先超时断开，日志记为「中断」。开启心跳后网关会定期发 : keepalive 注释帧保活，客户端就不会再误判空闲。
  • 结果三态：成功 正常完成；失败 上游报错（计入错误率）；中断 客户端自己断开了连接（超时、取消、关闭页面），不计入错误率、也不冷却密钥/供应商。
  • 首字超时 / 停滞超时：错误信息里会写明「首字超时（N 秒内上游无响应）」或「流中停滞超时（N 秒无新数据）」，前者已自动重试过，后者是流式输出中途中断。
  • 502 all_members_failed：上游全部失败，到「统计 → 最近请求」或「日志」看具体上游错误。
  • 503 no_available_member：平台模型没有启用成员，或所有成员正在冷却。

更多问题：先看「日志」页错误信息，再开「调试模式」复现一次，基本都能定位。
